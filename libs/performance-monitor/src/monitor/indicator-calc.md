以下是前端核心性能指标的计算方法详解，涵盖计算逻辑、关键API及行业标准：

### ⚙️ **一、核心Web Vitals指标**

1. **LCP（最大内容渲染时间）**

   * **计算方式**：

     * 通过 `PerformanceObserver`监听 `largest-contentful-paint`条目，取渲染时间最大值。
     * 公式：`LCP = entry.startTime - navigationStart`（`navigationStart`通过 `performance.timing.navigationStart`获取）。
   * **优化阈值**：

     * ≤2.5秒（优秀），2.5-4秒（需优化），>4秒（较差）。
2. **INP（交互到下一次渲染延迟）**

   * **计算方式**：

     * 监听所有用户交互（点击、输入等），记录事件开始到下一次渲染的时间差，取最长延迟（98百分位数）。
     * 使用 `event`类型性能条目，过滤 `durationThreshold`（默认40ms）以下的低耗时操作。
   * **优化阈值**：

     * ≤200ms（优秀），200-500ms（需优化），>500ms（较差）。
3. **CLS（累积布局偏移）**

   * **计算方式**：

     * 公式：`CLS分数 = 影响分数 × 距离分数`。

       * **影响分数**：不稳定元素在视口中的面积占比（如元素A占屏幕50%，偏移后与原始区域重叠25%，则影响分数为0.75）。
       * **距离分数**：元素移动距离 / 视口最大尺寸（垂直或水平方向取较大值）。
     * 仅统计无用户交互的偏移（`hadRecentInput=false`）。
   * **优化阈值**：

     * ≤0.1（优秀），0.1-0.25（需优化），>0.25（较差）。

---

### ⚙️ **二、加载性能指标**

1. **FCP（首次内容渲染时间）**

   * **计算方式**：

     * 监听 `paint`事件中的 `first-contentful-paint`条目，取 `entry.startTime - navigationStart`。
     * 与FP（首次绘制）区别：FP可能仅为背景色渲染，FCP需包含文本/图片等有效内容。
   * **优化阈值**：

     * ≤1.8秒（优秀），>3秒（需优化）。
2. **TTFB（首字节时间）**

   * **计算方式**：

     * `TTFB = responseStart - requestStart`（通过 `performance.timing`或 `navigation`条目获取）。
   * **优化阈值**：

     * ≤200ms（优秀），>600ms（需优化）。
3. **TTI（可交互时间）**

   * **计算方式**：

     * 需满足两个条件：

       1. 主线程连续5秒无长任务（>50ms）。
       2. 关键资源加载完成（如JS、CSS）。
     * 弱网环境下静默期阈值延长至7秒。
   * **优化阈值**：

     * ≤5秒（优秀），>7秒（需优化）。

---

### ⚙️ **三、交互与渲染性能指标**

1. **TBT（总阻塞时间）**

   * **计算方式**：

     * 统计FCP到TTI之间所有长任务（>50ms）的阻塞时间总和（任务时长 - 50ms）。
   * **优化阈值**：

     * ≤200ms（优秀），>600ms（需优化）。
2. **FID（首次输入延迟）**

   * **计算方式**：

     * 监听 `first-input`条目，取 `processingStart - startTime`（已逐渐被INP取代）。
   * **优化阈值**：

     * ≤100ms（优秀），>300ms（需优化）。

---

### 📊 **四、性能指标阈值标准汇总**


| **指标** | **优秀** | **需优化** | **较差** |
| -------- | -------- | ---------- | -------- |
| **LCP**  | ≤2.5秒  | 2.5-4秒    | >4秒     |
| **INP**  | ≤200ms  | 200-500ms  | >500ms   |
| **CLS**  | ≤0.1    | 0.1-0.25   | >0.25    |
| **FCP**  | ≤1.8秒  | 1.8-3秒    | >3秒     |
| **TTFB** | ≤200ms  | 200-600ms  | >600ms   |
| **TTI**  | ≤5秒    | 5-7秒      | >7秒     |

### ⚡ **五、技术实现要点**

1. **API使用规范**：

   * 优先用 `PerformanceObserver`（非弃用的 `performance.timing`），设置 `buffered:true`捕获历史数据。
   * 跨域资源需添加 `Timing-Allow-Origin`头，否则 `Resource Timing`返回0。
2. **动态修正策略**：

   * 移动端阈值放宽30%（如FCP阈值 = 1.8秒 × 1.3）。
   * SPA路由切换时重置CLS累计值，避免跨路由污染。
3. **上报优化**：

   * 使用 `navigator.sendBeacon`异步上报，失败时降级为 `fetch+keepalive`。

---

### 💎 **总结**

前端性能指标的计算需结合**用户感知量化**（如LCP/CLS）、**技术过程分解**（如TTFB/TTI）及**环境动态适配**（设备/网络阈值）。开发中应通过 `Performance API`精准采集数据，并依据行业阈值针对性优化，例如：

* 优化LCP：预加载关键资源、压缩图片、减少渲染阻塞脚本。
* 降低CLS：为动态元素预设占位空间、避免未定义尺寸的图片/广告。
* 提升INP：拆分长任务、使用Web Worker、优化事件处理逻辑。
